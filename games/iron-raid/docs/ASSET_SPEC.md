# IRON RAID 에셋 규격 (외부 에셋 교체용)

이 문서는 게임 코드가 **이미 쓰고 있는** 텍스처 이름, 프레임 이름, 크기, 기준점, 타이밍을 그대로 정리한 것이다. 이 규격에 맞춘 파일을 `content/`에 넣고 `content/manifest.json`에 등록하면 코드 수정 없이 게임에 반영된다.

- 지금 게임의 모든 그림과 소리는 코드로 생성된 **임시(placeholder)** 다 (`src/art/`, `src/sfx.js`).
- 로더(`src/scenes/Boot.js`)는 먼저 임시 텍스처를 전부 만든 다음, manifest에 있는 파일로 **같은 이름의 텍스처를 교체**한다.
- 파일이 없거나 규격이 틀리면 그 항목만 거부하고 임시 에셋을 그대로 쓴다. 게임은 멈추지 않는다. 거부 사유는 브라우저 콘솔에 `[content]`로 출력된다.
- 기계가 읽는 원본 규격: `spec/textures.json` (텍스처·프레임 목록), `spec/animations.json` (애니메이션 순서·속도).
- 지금 임시 그래픽을 규격 그대로 뽑은 참조 파일: `content-reference/` (PNG + 아틀라스 JSON 48종). **새 에셋은 이 파일을 복사해서 위에 그리는 것이 가장 안전하다.**

---

## 1. 폴더 구조와 파일명

```
games/iron-raid/
├── content/                  ← 외부 에셋을 넣는 곳 (빌드 시 dist/iron-raid/content/ 로 복사)
│   ├── manifest.json         ← 교체할 항목 목록 (비어 있으면 전부 임시 에셋)
│   ├── sprites/
│   │   ├── player.png        ← 파일명 = 텍스처 키
│   │   ├── player.json       ← 프레임이 여러 개인 텍스처는 아틀라스 JSON 동봉
│   │   └── sky.png           ← 한 장짜리 텍스처는 PNG만
│   └── audio/
│       ├── sfx/pistol.ogg    ← 파일명 = 효과음 이름
│       └── bgm/stage.ogg     ← 파일명 = BGM 이름
├── content-reference/        ← 현재 임시 그래픽의 참조 시트 (수정 금지, 복사해서 사용)
│   ├── sprites/*.png, *.json
│   └── manifest.example.json ← 48종 전부를 등록한 예시 manifest
├── spec/textures.json        ← 텍스처별 크기·프레임 이름·기준점
└── spec/animations.json      ← 애니메이션 프레임 순서·fps
```

파일명 규칙

- 스프라이트: `sprites/<텍스처 키>.png` (+ `sprites/<텍스처 키>.json`). 키는 4장 표의 값을 대소문자까지 그대로 쓴다.
- 효과음: `audio/sfx/<효과음 이름>.<ext>`, BGM: `audio/bgm/<stage|boss>.<ext>`.
- 실제 로딩은 manifest의 경로를 따르므로 위 규칙은 권장 사항이지만, 협업 시 이 이름을 지켜 달라.
- 경로는 `content/` 기준 상대 경로, 슬래시(`/`) 구분, 영문 소문자·숫자·`_`·`-`만 사용.

## 2. manifest.json 형식

```json
{
  "version": 1,
  "sprites": {
    "player":  { "image": "sprites/player.png", "atlas": "sprites/player.json" },
    "sky":     { "image": "sprites/sky.png" }
  },
  "sfx": { "pistol": "audio/sfx/pistol.ogg" },
  "bgm": { "stage": "audio/bgm/stage.ogg", "boss": "audio/bgm/boss.ogg" }
}
```

- 교체하고 싶은 항목만 적는다. 적지 않은 항목은 임시 에셋 그대로.
- 프레임이 여러 개인 텍스처(4장 표에서 프레임 수 > 0)는 `atlas`가 **필수**, 한 장짜리는 `image`만.

## 3. 스프라이트 공통 규격

| 항목 | 규격 |
| --- | --- |
| 파일 형식 | PNG, RGBA 8bit (또는 투명 포함 인덱스 PNG) |
| 배율 | **1배**. 게임 해상도는 384×216이고 화면에 정수배로 확대된다 (nearest-neighbor). 미리 확대한 이미지는 거부된다. |
| 투명 | 배경은 완전 투명(알파 0). 가장자리 반투명 안티앨리어싱 금지 (도트가 뭉개짐) |
| 방향 | **모든 캐릭터·차량은 오른쪽을 보고 그린다.** 왼쪽은 게임이 좌우 반전한다. (적 APC·헬기도 오른쪽을 보게 그림) |
| 프레임 크기 | 한 텍스처 안의 모든 프레임은 4장 표의 크기와 **정확히 같아야** 한다 (다르면 거부). 판정 박스·총구 위치가 이 크기를 기준으로 계산되기 때문 |
| 프레임 배치 | 시트 안 배치는 자유 (가로 한 줄, 격자 등). 위치는 아틀라스 JSON이 알려 준다 |
| 트리밍 | `trimmed: false` 권장. 트리밍을 쓰면 `sourceSize`가 4장 표의 프레임 크기와 같아야 한다 |
| 회전 | `rotated: false` (회전 패킹 금지) |
| 외곽선 | 권장: 1px `#1b1b22` 외곽선 (현재 스타일) |
| 팔레트 | 권장: `src/palette.js`의 색. 기획서 6.2 팔레트와 같음. 스프라이트당 16색 이하 권장 |
| 타일 텍스처 | `far`, `mid`, `ground`, `dock`, `water_0`, `water_1`은 가로로 반복된다. **높이만 맞으면 폭은 자유**, 좌우 끝이 이어지게 그린다 |

### 아틀라스 JSON 형식 (Phaser / TexturePacker "JSON Hash")

```json
{
  "frames": {
    "p_idle_0": {
      "frame": { "x": 0, "y": 0, "w": 40, "h": 44 },
      "rotated": false,
      "trimmed": false,
      "spriteSourceSize": { "x": 0, "y": 0, "w": 40, "h": 44 },
      "sourceSize": { "w": 40, "h": 44 }
    }
  },
  "meta": { "image": "player.png", "size": { "w": 640, "h": 480 }, "scale": "1" }
}
```

- `frames`의 키 = 프레임 이름. `spec/textures.json`에 있는 이름이 **하나라도 빠지면 그 텍스처 전체가 거부**된다. 추가 프레임은 무시된다.
- TexturePacker, Aseprite(“Export Sprite Sheet → JSON Hash”, 태그 대신 프레임 이름을 직접 지정), Free Texture Packer 등으로 만들 수 있다. 참조 파일(`content-reference/sprites/*.json`)이 정확한 예시다.

## 5. 애니메이션 규격

게임은 Phaser의 애니메이션 시스템 대신 **코드가 프레임 이름을 직접 고른다.** 그래서 새 에셋은 프레임 **이름과 개수**만 맞추면 되고, 순서·속도는 코드가 정한다. 전체 목록은 `spec/animations.json`.

```json
{
  "animations": {
    "player": {
      "p_run_fwd": { "frames": ["p_run_fwd_0_0", "...", "p_run_fwd_0_7"], "fps": 12, "loop": true,
                     "note": "running, aim fwd; the _1_ set (muzzle flash) replaces it for 0.06s after each shot" }
    }
  }
}
```

- `fps: 0`은 고정 자세이거나 코드가 시간에 맞춰 바꾸는 프레임이다 (`note`에 타이밍).
- 프레임 수를 늘리고 싶으면(예: 달리기 8 → 12) 코드 수정이 필요하다. 그때는 `spec/animations.json`과 해당 `src/objects/*.js`를 같이 바꾼다.

주요 타이밍

| 대상 | 애니메이션 | 프레임 | 속도 |
| --- | --- | --- | --- |
| 플레이어 | 달리기 | 8 | 12fps 루프 |
| 플레이어 | 서서 숨쉬기 | 2 | 2.5fps 루프 |
| 플레이어 | 사격 화염 | `_1` 프레임 | 발사 후 0.06초 |
| 플레이어 | 수류탄 | 3 | 0.1초씩 |
| 플레이어 | 칼 | 2 | 0.08초 + 0.14초 |
| 플레이어 | 사망 | 6 | 10fps, 이후 깜빡임 |
| 적 병사 | 걷기 / 칼 달리기 / 도망 | 8 | 11 / 16 / 14fps |

## 6. 오디오 규격

| 항목 | 효과음 (sfx) | 배경음악 (bgm) |

| 형식 | OGG Vorbis 권장 (`.ogg`). `.mp3`, `.wav`, `.m4a`도 동작 | OGG Vorbis 권장 |
| 샘플레이트 | 44.1kHz 또는 48kHz | 44.1kHz 또는 48kHz |

## 7. 교체 작업 순서 (예: 주인공 교체)

1. `content-reference/sprites/player.png`와 `player.json`을 `content/sprites/`로 복사한다.
2. PNG의 각 40×44 칸 안에 새 그림을 그린다. 발은 맨 아래 줄, 몸 중심은 x=20, 총끝은 4.1의 총구 위치에 맞춘다. 칸 배치를 바꿨다면 JSON의 `frame` 좌표도 맞춘다.
3. `content/manifest.json`에 등록한다.
   ```json
   { "version": 1, "sprites": { "player": { "image": "sprites/player.png", "atlas": "sprites/player.json" } }, "sfx": {}, "bgm": {} }
   ```
4. 규격 검사: `npm run iron-raid:check` → `all entries valid`가 나와야 한다.
5. 게임 실행 후 브라우저 콘솔에서 `[content] {"applied":["player"],...}` 확인. 거부됐으면 `kept placeholder for "player": 사유`가 나온다.

## 8. 규격을 바꾸고 싶을 때

프레임 크기(예: 캐릭터 64×64), 프레임 수, 기준점을 바꾸려면 코드도 바꿔야 한다. 관련 위치:

- 판정 박스·총구: `src/objects/Player.js` (`body.setSize`, `muzzle()`), `Soldier.js`, `Pow.js`, `Tank.js`, `Vehicles.js`, `Boss.js`
- 프레임 선택·타이밍: 각 오브젝트의 `update()` / `pickFrame()`
- 임시 그래픽 생성: `src/art/*.js` (규격을 바꾸면 여기도 새 크기로 맞춰야 로더의 비교 기준이 바뀐다)
- 바꾼 뒤 `npm run iron-raid:reference`로 `spec/`과 `content-reference/`를 다시 만든다.
